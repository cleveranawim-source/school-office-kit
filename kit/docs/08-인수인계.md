# 인수인계 — 내가 떠나도 사이트가 남도록

교사가 만든 학교 사이트가 가장 자주 무너지는 때는 **만든 사람이 전근 가거나 업무가 바뀔 때**다. 공립학교는 순환 근무가 있어서 몇 년 안에 거의 반드시 온다. 처음부터 아래를 지켜 두면 이어받는 사람이 하루 만에 운영을 시작할 수 있다.

## 처음 만들 때 (0단계에서)

1. **계정 명의를 학교 공용으로.** GitHub·Supabase·Vercel·AI 회사 계정을 학교 공용 메일(예: 정보부 공용 계정)로 만든다. 개인 계정으로 이미 만들었다면, 조직(팀)을 만들어 학교 공용 계정을 소유자로 함께 넣어 둔다.
2. **결제 수단**이 개인 카드라면, 언제 학교 예산으로 옮길지 관리자와 정해 둔다.
3. **비밀 값 보관 장소**를 정한다. `.env.local`의 값들을 학교가 관리하는 안전한 곳(예: 학교 비밀번호 관리 도구, 봉인한 문서)에 따로 둔다. 대화방·메일에 붙여 넣지 않는다.

## 운영하는 동안

- `progress.md`의 「운영 메모」에 다음을 적어 둔다(값은 빼고 이름과 위치만).
  - 환경변수 이름과 각각 어디서 받았는지
  - 크론 등록 내역(이름, 시각, 부르는 주소)
  - 학기마다 할 일(교직원 명단 갱신, 시간표 업로드, 담임 배정, 외부 링크 만료 갱신 등)
  - 외부 연동마다 담당자(예: 보건 선생님께 매년 2월 새 공유 링크 받기)
- 관리자 권한을 가진 교사를 **두 명 이상** 둔다.

## 넘길 때 체크리스트

- [ ] 이어받는 분을 각 서비스 계정·조직에 소유자로 추가했다
- [ ] 비밀 값 보관 장소와 여는 방법을 전달했다
- [ ] `progress.md` 운영 메모를 함께 읽었다
- [ ] 이어받는 분이 직접 한 번 배포해 봤다(작은 글자 하나 고치기)
- [ ] 이어받는 분이 학기 작업 하나(예: 교직원 추가)를 직접 해 봤다
- [ ] 내 개인 계정을 조직에서 뺐다(넘긴 뒤 한 달쯤 지나서)

## 이어받는 분이 개발자가 아닐 때

이 저장소를 Claude Code나 Codex로 열고 「운영을 이어받았어. 지금 상태를 알려 줘」라고 말하면, 에이전트가 `school-profile.md`·`progress.md`를 읽고 설명한다. 그래서 이 두 파일을 늘 최신으로 두는 것이 가장 좋은 인수인계다.
