# 구축 순서와 관문

인터뷰가 끝나면 에이전트는 이 문서를 바탕으로 그 학교의 단계 계획을 짜서 `progress.md`에 적는다. 단계마다 **관문**을 모두 통과해야 다음으로 간다.

## 원본 학교는 어떻게 만들었나 (참고)

| 기간 | 한 일 |
|---|---|
| 1일차 | 설계 문서, 이름 로그인·비밀번호 변경·역할·교사 관리, 디자인 토큰·앱 틀, 시간표 변환기·업로드·조회 |
| 2일차 | 자료실(패들렛 83건 이관), 일정(구글 캘린더)·공지, 급식, 아침 알림(웹푸시·pg_cron) |
| 3일차 | 점심 알림, 진도표, 결석 접수 봇·담임 배정·한글 서식, 체험학습 봇, 주간소식, AI 도우미(챗봇) |
| 1주차 이후 | 보건실, 앱 안 링크 보기, 공지 보존 기한 |
| 2주차 | 업무 요청 「넵」 |
| 3주차 | 교실 칠판 알림, 세특 도우미 |
| 4주차 | AI 확인 카드(수업교체·신청·가정통신문), 자료실 AI 색인, 내 서명·서명부·파일 서명, 조직표 |
| 5주차 | AI 비용 절감, 점검 세트, 답 평가 |

보이는 흐름: **처음 사흘에 「읽기 위주의 정보 허브」를 깔고**(로그인·시간표·자료실·일정·공지·급식·알림), 그 뒤 일이 오가는 큰 모듈을 하나씩 「설계 → 계획 → 구현」으로 붙였다. 원본 학교의 속도는 개발자 한 명이 매일 붙어 있었던 경우다. **다른 학교는 이보다 천천히, 단계마다 시범 사용자 반응을 보며** 가는 편이 안전하다.

## 단계 계획 짜는 법

1. 0단계(준비)와 1단계(뼈대)는 모든 학교가 같다.
2. 2단계는 **빠른 첫 성공** — 급식처럼 쉽고 매일 보는 것 하나 + 공지.
3. 3단계부터는 **선생님이 인터뷰에서 말한 불편**을 덜어 주는 모듈을 앞으로 당긴다. 단, 「먼저 있어야 할 것」(`02-모듈카탈로그.md` 표)을 지킨다.
4. 핵심 모듈이 갖춰지면 **첫 공개**(시범 사용자 3~5명 → 교직원 전체).
5. 추천·선택 모듈은 공개 뒤 반응을 보고 고른다.

## 단계별 내용과 관문

### 0단계 — 준비

→ `00-준비물.md`의 0단계 관문.

### 1단계 — 뼈대

로그인·계정, 관리(교사 관리, 설정 표), 앱 틀(메뉴·디자인 토큰·하단 탭), 학교 설정 파일, 공통 부품(세션 확인·서울 날짜·크론 껍데기), 테스트 세 층, 배포.

→ `04-뼈대설계.md`의 1단계 관문 + `05-보안기준선.md` A·B·C.

### 2단계 — 첫 성공

급식, 공지, 홈(껍데기 — 오늘 날짜·급식·공지).

관문:
- [ ] 시범 사용자 1명이 자기 휴대폰으로 로그인해 오늘 급식과 공지를 봤다
- [ ] 공지 보존 기한(24시간·30일)이 RLS 테스트로 확인된다
- [ ] 정리 크론이 시험용 DB에서 한 번 돌았다

### 3단계 — 시간과 일정

시간표(변환기 포함), 교시 시각, 일정(캘린더·공휴일), 담임 배정, 홈에 오늘 시간표·일정.

관문:
- [ ] 이 학교 시간표 파일 하나를 변환해, 교사 3명·학급 3개를 손으로 대조해 맞다
- [ ] 「지금 교시」가 서울 시각으로 맞다(UTC 자정 경계 테스트 포함)
- [ ] 종일 일정·공휴일이 하루 밀리지 않는다
- [ ] 시간표에 있는데 계정이 없는 교사가 미리보기에 경고로 뜬다

### 4단계 — 자료와 알림

자료실(+앱 안 링크 보기, 기존 자료 이관), 알림(웹푸시, 아침 요약, 시험 잠금).

관문:
- [ ] 20MB 파일 업로드·내려받기가 휴대폰에서 된다(아이폰 홈 화면 앱 포함)
- [ ] 다른 교사 폴더를 가리키는 파일 경로로 글을 넣으면 거부된다(RLS 테스트)
- [ ] 시험 잠금 상태에서 아침 요약이 시범 사용자 1명에게만 간다
- [ ] 크론을 두 번 불러도 알림은 한 번만 간다
- [ ] 아이폰에서 알림을 누르면 그 화면으로 간다
- [ ] `pg_cron` 등록 SQL을 저장소에 남겼다

### 첫 공개

- [ ] 시범 사용자 3~5명이 1주일 써 봤고, 받은 의견을 `progress.md`에 적었다
- [ ] 초기 비밀번호 배부 방법과 「처음 쓰는 법」 한 쪽 안내를 준비했다
- [ ] 관리자 두 명 이상
- [ ] `05-보안기준선.md` 전체 점검
- [ ] 문의 창구(누구에게, 어떻게)를 정했다

### 그 다음 — 학교가 고른 순서로

추천·선택 모듈을 하나씩. 큰 모듈(업무 요청, 칠판, 서명, AI)은 각각:

1. 설계 문서(합의한 결정 표, 범위 밖 목록)
2. 계획(작게 나눈 작업, 실패하는 테스트부터)
3. 구현
4. 그 모듈의 관문(카탈로그의 「지킬 것」을 테스트로 확인) + 시범 사용자 확인
5. 공개 + 전체 푸시 안내

모듈 서너 개를 붙일 때마다 **전수 점검**을 한 번 한다(권한·보존 기한·알림 대상·휴대폰 화면). 원본 학교는 첫 점검에서 한 번에 16건을 찾았다.

## 하지 않을 것 (처음부터 범위 밖으로)

- 전자결재·나이스를 대신하는 기능
- 학생·학부모 계정
- 교직원 채팅(메신저가 이미 있다)
- 화면 없이 쌓기만 하는 기록(보건 방문 기록 같은 것 — 학교 관행 확인 전에는)
