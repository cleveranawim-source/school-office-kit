# 구축 순서와 관문

인터뷰가 끝나면 에이전트는 이 문서를 바탕으로 그 학교의 단계 계획을 짜서 `progress.md`에 적는다. 단계마다 **관문**을 모두 통과해야 다음으로 간다.

## 원본 학교는 어떻게 만들었나 (참고)

| 기간 | 한 일 |
|---|---|
| 1일차 | 설계 문서, 이름 로그인·비밀번호 변경·역할·교사 관리, 디자인 토큰·앱 틀, 시간표 변환기·업로드·조회 |
| 2일차 | 자료실(패들렛 수십 건 이관), 일정(구글 캘린더)·공지, 급식, 아침 알림(웹푸시·pg_cron) |
| 3일차 | 점심 알림, 진도표, 결석 접수 봇·담임 배정·한글 서식, 체험학습 봇, 주간소식, AI 도우미(챗봇) |
| 1주차 이후 | 보건실, 앱 안 링크 보기, 공지 보존 기한 |
| 2주차 | 업무 요청 「넵」 |
| 3주차 | 교실 칠판 알림, 세특 도우미 |
| 4주차 | AI 확인 카드(수업교체·신청·가정통신문), 자료실 AI 색인, 내 서명·서명부·파일 서명, 조직표 |
| 5주차 | AI 비용 절감, 점검 세트, 답 평가, 보안 기준선, 알림함, 현황판, 교무부 직접 등록, AI 파일·주소 읽기, 칠판 시험 화면·예약 |
| 6주차 | 휴직, 학생 사진 명렬표, 공유 드라이브 AI 읽기, 공지를 현황판으로 합침, 결석 접수 공개 범위 스위치, **전수 점검 두 번**(보안 → 버그 → 작은 것 → 정리 순), 수업교체 계산을 사이트 안으로, 그날 시간표(학사일정·교체 얹기), 넵 마감·넵 속 일정을 내 일정에, 아침·점심 「내 줄」, 칠판 쪽지·자동 쪽지, 교실 정하기, 행사 화면 |
| 7주차 | 받는 사람 고르기(조직도), AI가 먼저 챙기기(다음 주 미리 보기·새 문서 요약·홈 인사), 축하, 칠판 음성·수업 중 숨기기, 교체 고치기·관리자 대신 수락, 화면 전체 점검(글자 단계·접근성), 분실물 함, 날씨 안내(미리 보기), **넵을 업무 메신저로** |

보이는 흐름:
- **처음 사흘에 「읽기 위주의 정보 허브」를 깔고**(로그인·시간표·자료실·일정·공지·급식·알림), 그 뒤 일이 오가는 큰 모듈을 하나씩 「설계 → 계획 → 구현」으로 붙였다.
- 5주차부터는 새 모듈보다 **모듈 사이를 잇는 일**이 많았다. 같은 사실(오늘 내 수업 수, 쉬는 날, 바뀐 수업)을 홈·시간표·현황판·알림이 서로 다르게 세는 일이 생겨, 셈을 함수 하나로 모으고(「그날 시간표」 층이 이렇게 생겼다) 화면마다 그 함수를 부르게 고쳤다.
- 7주 동안 커밋이 약 1,000개다. 원본 학교의 속도는 개발자 한 명이 매일 붙어 있었던 경우다. **다른 학교는 이보다 천천히, 단계마다 시범 사용자 반응을 보며** 가는 편이 안전하다.

## 단계 계획 짜는 법

1. 0단계(준비)와 1단계(뼈대)는 모든 학교가 같다. 2~4단계도 핵심 모듈로 차례가 정해져 있고, 학교에서 정말 안 쓰는 핵심 모듈만 뺀다(`plan.mjs --skip`).
2. 2단계는 **빠른 첫 성공** — 급식처럼 쉽고 매일 보는 것 하나 + 공지 + 홈(껍데기).
3. 핵심 모듈이 갖춰지면(4단계 뒤) **첫 공개**(시범 사용자 3~5명 → 교직원 전체).
4. 5단계부터는 **선생님이 인터뷰에서 말한 불편**을 덜어 주는 모듈을 급한 순서로 넣는다. 단, 「먼저 있어야 할 것」(`02-모듈카탈로그.md` 표)을 지킨다. `plan.mjs`가 모자란 것을 끌어오고 순서를 맞춘다.
5. 그 밖의 추천·선택 모듈은 공개 뒤 반응을 보고 더 고른다.
6. 학생 정보가 걸린 모듈(학생 사진 명렬표, 분실물 함 학생용 보기, 결석 접수 공개 범위)은 **기본 꺼짐**으로 계획에 넣고, 교육청·학교 지침을 확인한 뒤에 켠다.

`modules.json`의 관계:
- **requires**: 반드시 먼저. 고르지 않았어도 끌어온다.
- **after**: 함께 고르면 그 뒤에.
- **touches**: 이 모듈을 만들 때 함께 손볼, 이미 있는 모듈이다(홈 카드, 현황판 칸, 내 일정 겹치기, AI 도구). `plan.mjs`가 「함께 손볼 곳」으로, `memo.mjs`가 설계 메모 5절로 알려 준다.

## 단계별 내용과 관문

### 0단계 — 준비

→ `00-준비물.md`의 0단계 관문.

### 1단계 — 뼈대

다음을 만든다.
- 로그인·계정(휴직·비활성 상태 포함), 관리(교사 관리, 설정 표)
- 앱 틀(메뉴·디자인 토큰·하단 탭), 학교 설정 파일
- 공통 부품: 세션 확인·서울 날짜·크론 껍데기·기능 문. 1분 틱은 처음 필요할 때 여기에 만든다.
- 테스트 세 층, 배포

→ `04-뼈대설계.md`의 1단계 관문 + `05-보안기준선.md` A·B·C·F. 덧붙여:
- [ ] 휴직(을 둔다면)·비활성 계정으로 로그인해 보고, 정해 둔 곳 밖의 화면·데이터 API가 닫혀 있다(RLS 테스트에 그 계정을 넣었다)
- [ ] 비밀번호를 여러 번 틀리면 잠시 막힌다

### 2단계 — 첫 성공

급식, 공지, 홈(껍데기 — 오늘 날짜·급식·공지). 공지의 전체 푸시는 4단계에서 잇는다.

관문:
- [ ] 시범 사용자 1명이 자기 휴대폰으로 로그인해 오늘 급식과 공지를 봤다
- [ ] 공지 보존 기한(24시간·30일)이 RLS 테스트로 확인된다
- [ ] 정리 크론이 시험용 DB에서 한 번 돌았다

### 3단계 — 시간과 일정

시간표(변환기 포함), 교시 시각, 일정(캘린더·공휴일), 담임 배정, 홈에 오늘 시간표·일정. 단축 수업·교체를 얹는 「그날 시간표」는 아직 만들지 않는다 — 기본 시간표가 맞는 것부터 확인한다.

관문:
- [ ] 이 학교 시간표 파일 하나를 변환해, 교사 3명·학급 3개를 손으로 대조해 맞다
- [ ] 「지금 교시」가 서울 시각으로 맞다(UTC 자정 경계 테스트 포함)
- [ ] 종일 일정·공휴일이 하루 밀리지 않는다
- [ ] 쉬는 날 판정이 함수 하나이고, 이 학교 달력의 실제 제목(재량휴업일·방학식 등)으로 시험했다
- [ ] 시간표에 있는데 계정이 없는 교사가 미리보기에 경고로 뜬다

### 4단계 — 자료와 알림

자료실(+앱 안 링크 보기, 기존 자료 이관), 알림(웹푸시, 아침 요약, 시험 잠금 — 단체 발송을 한 사람에게만 보내는 시험 스위치, 공지 전체 푸시 잇기), 알림함(개인 알림 모음).

관문:
- [ ] 20MB 파일 업로드·내려받기가 휴대폰에서 된다(아이폰 홈 화면 앱 포함)
- [ ] 다른 교사 폴더를 가리키는 파일 경로로 글을 넣으면 거부된다(RLS 테스트), `../`가 든 경로는 서명 전에 거부된다
- [ ] 시험 잠금 상태에서 아침 요약이 시범 사용자 1명에게만 간다
- [ ] 크론을 두 번 불러도 알림은 한 번만 간다
- [ ] 아이폰에서 알림을 누르면 그 화면으로 간다
- [ ] 공지를 올리면 전체 푸시가 간다(시험 잠금으로 먼저)
- [ ] 개인 알림은 함수 하나를 지나 알림함에도 남고, 휴직·비활성 계정에는 가지 않는다
- [ ] `pg_cron` 등록 SQL을 저장소에 남겼다

### 첫 공개

- [ ] 시범 사용자 3~5명이 1주일 써 봤고, 받은 의견을 `progress.md`에 적었다
- [ ] 초기 비밀번호 배부 방법과 「처음 쓰는 법」 한 쪽 안내를 준비했다
- [ ] 관리자 두 명 이상
- [ ] `05-보안기준선.md` 전체 점검
- [ ] 문의 창구(누구에게, 어떻게)를 정했다
- [ ] 퇴직·휴직이 생겼을 때 누가 어떻게 계정을 바꾸는지 정했다

### 그 다음 — 학교가 고른 순서로

추천·선택 모듈을 하나씩. 큰 모듈(넵, 수업교체, 칠판, 서명, AI)은 각각:

1. 설계 문서(합의한 결정 표, 범위 밖 목록)
2. 계획(작게 나눈 작업, 실패하는 테스트부터)
3. 구현
4. 그 모듈의 관문(카탈로그의 「지킬 것」을 테스트로 확인) + 시범 사용자 확인
5. 공개 + 전체 푸시 안내

새 기능은 **관리자에게만 먼저**(기능 문 — `04-뼈대설계.md` 5절) 열어 운영자가 실제로 써 본 뒤 공개한다. 학생이 보는 출력(교실 칠판)과 단체 알림은 미리 보기 동안 보내지 않는다.

**순서에서 자주 걸리는 것**:
- **조직표 → 넵**: 넵의 부서·묶음 발송과 대화방은 조직표가 채워져 있어야 동작한다.
- **수업교체 → 그날 시간표·현황판**: 교체를 쓰기 시작하면 홈 수업 수, 시간표, 진도표 칸, 빈 교실 찾기가 모두 교체를 얹은 「그날 시간표」를 써야 숫자가 맞는다. 그래서 `plan.mjs`는 수업교체를 고르면 그날 시간표를 먼저 넣는다. 현황판의 「바뀐 수업」 칸도 수업교체가 있어야 채워진다.
- **1분 틱**: 넵 배달·보건실 읽기·칠판 자동 쪽지·날씨 안내는 크론 하나에 얹는다. 두 번째 1분 작업이 생길 때 따로 만들지 않는다.
- **AI 도우미는 읽을 모듈 뒤에**: 모듈이 생길 때마다 AI 읽기 도구·확인 카드가 하나씩 늘어난다(`07-AI도우미.md`).

**함께 손볼 곳을 잊지 않는다**: 모듈 하나를 붙이면 홈 카드, 현황판 칸, 내 일정 겹치기, AI 도구, 아침 알림 줄이 함께 바뀐다. 같은 사실을 두 곳 이상이 보이면 셈 함수 하나를 같이 쓴다(`06-함정노트.md` 114). 설계 메모 5절의 「함께 손볼 곳」을 관문 전에 하나씩 지운다.

모듈 서너 개를 붙일 때마다 **전수 점검**을 한 번 한다(권한·보존 기한·알림 대상·휴대폰 화면, 화면에서 감춘 열이 데이터 API로 보이는지). 원본 학교는 첫 점검에서 한 번에 16건을 찾았고, 6주차에는 점검 두 번에서 나온 수십 건을 **보안 → 버그 → 작은 것 → 정리** 순서로 나눠 고쳤다.

## 하지 않을 것 (처음부터 범위 밖으로)

- 전자결재·나이스를 대신하는 기능
- 학생·학부모 계정. 학생이 보는 화면(교실 칠판, 분실물 학생용 보기)은 계정 대신 긴 열쇠 주소로 연다. 교실 칠판은 시작 전에 학교 정보 담당과 교실 PC 설정을 상의하고, 분실물 학생용 보기는 기본 꺼짐으로 두었다가 학교 지침을 확인한 뒤 켠다.
- **처음부터** 교직원 메신저 만들기. 원본 학교도 「넵」을 업무 요청(읽음·답 받기·배달 규칙)으로 시작했고, 자리 잡은 7주차에야 메신저 업무방을 옮기는 업무 메신저로 키웠다. 키우려면 배달 규칙(수업 중·근무 시간 밖 미루기)·보존 기한·첨부 정리를 먼저 정한다.
- 화면 없이 쌓기만 하는 기록(보건 방문 기록 같은 것 — 학교 관행 확인 전에는)
- 학생 사진·건강 정보를 새로 모으는 기능(교육청·학교 지침을 확인하기 전에는)
