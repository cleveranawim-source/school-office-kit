## 1. 아이폰·홈 화면 앱

1. ★★★ **하단 탭이 본문 중간에 떠 보이거나 스크롤에 딸려 올라온다** → 아이폰은 주소창을 접었다 펼 때 `position: fixed` 요소를 늦게 그린다. 화면 끝을 당기는 되튐도 같은 현상 → **하단 탭은 `fixed`가 아니라 본문 흐름 끝의 `sticky bottom-0`. `html, body { overscroll-behavior-y: none }`.**
2. ★★★ **입력칸을 누르면 화면이 확대되고, 가로로 밀면 페이지 전체가 움직인다** → 아이폰은 글자 16px 미만 입력칸에서 확대한다. 밀어 낸 카드가 화면 밖으로 나가면 문서 폭이 늘어난다 → **입력칸 `font-size: max(16px, 1em)`, `touch-action: manipulation`. 스와이프 영역은 `overflow-x: clip` + `touch-action: pan-y pinch-zoom`.**
3. ★★★ **홈 화면 앱에서 파일을 받으면 파일 화면으로 넘어가 돌아올 단추가 없다** → 독립 창에서 `<a download>`로 이동했기 때문 → **fetch로 받아 휴대폰은 `navigator.share({ files })` 공유 창, PC는 blob 내려받기.**
4. ★★★ **홈 화면 앱에서 바깥 링크를 누르면 다른 브라우저로 튀어 나간다** → `target=_blank` → **앱 안 보기 화면(iframe)으로 열고, 끼워 넣기를 막는 사이트만 같은 창으로(64번).**
5. ★★★ **알림을 눌러도 아이폰에서는 그 화면으로 안 간다** → iOS 서비스 워커에는 `WindowClient.navigate()`가 없다 → **창을 `focus()`한 뒤 `postMessage({ type: "open", url })`로 건네고, 페이지가 이동한다. 같은 출처 경로(`/`로 시작, `//` 아님)만 따른다.**
6. ★★★ **아이폰에서 알림 켜기가 안 되거나 「불러오는 중」에서 멈춘다** → iOS는 **홈 화면에 추가한 앱에서만** 웹푸시를 받는다. 서비스 워커 등록이 실패하면 `serviceWorker.ready`가 영원히 기다린다 → **홈 화면 앱인지 검사해 「홈 화면에 추가」 안내를 따로 보여 주고, `ready`에 5초 제한.**
7. ★★★ **`sw.js`를 고쳤는데 하루씩 옛 동작을 한다** → 브라우저가 `sw.js`를 캐시하고 새 워커는 대기한다 → **`/sw.js`에 `Cache-Control: no-cache`, install에서 `skipWaiting()`, activate에서 `clients.claim()`. 화면을 캐시하지 않는 워커일 때만 안전.**
8. ★★ **휴대폰이 잠들면 쓰던 AI 답이 사라진다** → 스트림이 끊김 → **서버는 화면이 끊겨도 그때까지 만든 답을 저장한다.**
9. ★★ **사파리 비공개 모드에서 화면이 깨진다 / 메뉴 이모지가 기기마다 다르다 / 탭 높이가 어긋난다** → localStorage는 접근만 해도 예외를 던진다. 이모지 글꼴은 OS마다 다르다. 홈 막대 여백은 기기마다 다르다 → **저장소 접근은 모두 try/catch. 메뉴는 선 아이콘. 탭 높이는 실측해서 CSS 변수로.**
10. ★★ **안드로이드에서 「홈 화면에 추가」한 특수 화면(교실 칠판)이 교사용 첫 화면으로 열린다** → 공용 매니페스트의 `start_url`이 `/` → **용도가 다른 화면에는 전용 매니페스트(start_url·scope·이름).**

## 2. 한글·날짜·시간대

11. ★★★ **이름을 정확히 쳤는데 「찾을 수 없음」** → 자판에 따라 한글이 자모로 쪼개져(NFD) 들어오고 공백이 섞인다 → **비교 전에 `normalize("NFC")` + 공백 제거. 초성 검색 지원. 한 사람으로 좁혀질 때만 자동 선택.**
12. ★★★ **자정~오전 9시에 「오늘 일정」이 하루 어긋난다 / 종일 일정이 하루 밀린다** → 서버(UTC)에서 오늘을 계산했다. 캘린더(ICS)의 종일 일정을 서버 시간대 날짜로 만들었다 → **「오늘」은 항상 `Asia/Seoul`로. 하루 범위는 `YYYY-MM-DDT00:00:00+09:00`. 종일 일정은 연·월·일만 꺼내 서울 자정으로 다시 만든다.**
13. ★★★ **마감 시각이 9시간 어긋나 「이미 지난 시각」으로 거부된다** → `<input type="datetime-local">` 값에는 시간대가 없는데 UTC 서버가 그대로 읽었다 → **서버에서 `${값}:00+09:00`으로 읽는다. 서버 시간대와 무관하게 통과하는 테스트.**
14. ★★★ **크론이 엉뚱한 시각·요일에 돈다** → pg_cron·Vercel 크론은 UTC. 서울 08시는 UTC 전날 23시라 **요일까지 하루 밀린다** → **평일 08:00~17:59 서울 = `* 23 * * 0-4` + `* 0-8 * * 1-5` 두 줄. 평일 07:50 = `50 22 * * 0-4`. 매일 03:00 = `0 18 * * *`. 식 옆에 서울 시각을 주석으로.**
15. ★★ **「1월 5일」이 작년 날짜로 저장된다 / 학년도 정리가 어긋난다** → 연도 없는 날짜를 그대로 읽었다. 학년도는 3월에 시작한다 → **연도 없는 날짜는 한 달 넘게 지난 날이면 내년으로. 학년도 경계는 3월 1일.**
16. ★★ **기념일(국군의날 등)에 알림이 쉰다 / 대체공휴일에도 「다음 수업 월요일」** → 공휴일 캘린더에 기념일이 섞여 있다. 다음 수업일 계산에서 공휴일을 안 봤다 → **「공휴일」로 표시된 것만 휴일로. 다음 수업일은 공휴일을 건너뛰어 찾는다.**
17. ★★ **시트의 날짜 칸을 엉뚱하게 찾는다** → 학교 시트의 「10월」 탭이 작년 달력 복사본이라 요일이 맞지 않았다 → **요일을 계산하지 말고 시트에 적힌 날짜로 칸을 찾는다. 날짜 키의 뜻을 바꿀 때는 저장된 키도 옮긴다.**
18. ★★ **「수행 평가」가 「수행함 평가」로 바뀐다** → 종결어미 보정 정규식이 문장 중간까지 고쳤다 → **한국어 문체 보정은 문장 끝에서만. 보이지 않는 특수 문자는 이스케이프로 쓰고 회귀 테스트.**
19. ★★★ **내려받은 한글 파일 이름이 「%EC%A0…」로 저장된다** → 서명 URL 라이브러리가 이름을 두 번 인코딩했다. 이미 디코드된 경로 값을 한 번 더 디코드했다 → **인코딩은 정확히 한 번. 파일 이름이 든 다운로드는 실제로 받아서 확인한다.**

## 3. Supabase

20. ★★★ **로그인 안 한 방문자가 교직원 명단을 읽을 수 있었다** → 뷰는 소유자 권한으로 돌아 RLS를 우회하고, Supabase 기본 권한 때문에 익명 SELECT가 남았다 → **표·뷰마다 `revoke … from anon, public`을 명시하고, 익명 거부 테스트.**
21. ★★★ **가드 트리거가 서버 작업까지 막는다 / 정책끼리 무한 재귀** → 시크릿 키로 실행하면 `auth.uid()`가 null이라 `is_admin()`이 false. 정책 안에서 다른 표를 읽으면 재귀 → **트리거에 「`auth.uid()`가 null이면 서버이므로 통과」 분기를 주석과 함께. 재귀는 `security definer` 함수로 끊는다.**
22. ★★★ **화면에 보이는데 「처리」를 눌러도 반영이 안 되고 오류도 없다** → 읽기와 수정 정책의 기준이 달랐다. RLS에 막힌 수정은 「0행 성공」으로 끝난다 → **보이는 것은 고칠 수 있게 두 정책을 맞추고, 반영된 행 수를 확인해 실패를 화면에 띄운다.**
23. ★★★ **크론이 상태를 엉뚱하게 되돌린다 / 이름이 빈칸** → 크론에서 로그인 세션 클라이언트로 읽어 RLS가 0행을 줬다 → **크론·백그라운드 작업은 시크릿 키로 읽는다. 남의 이름은 이름·부서만 담은 뷰로.**
24. ★★ **upsert가 매번 실패한다(42P10) / 「현재 버전」 전환이 실패한다(23505)** → 부분 유일 인덱스는 upsert 충돌 대상이 못 되고, 행마다 즉시 검사한다 → **기존 키를 조회해 넣기/고치기로 나눈다. 「현재 버전」 전환은 SQL 함수 안에서 「끄기 → 켜기」 두 문장으로.**
25. ★★★ **코드와 마이그레이션은 있는데 운영에서 「표 없음」** → 마이그레이션 적용(`db push`)을 빠뜨렸다 → **커밋 메시지에 「운영 DB 적용함/미적용」을 적는다. 새 표가 아직 없어도 화면은 죽지 않게.**
26. ★★★ **첨부 파일 노출·용량 우회 걱정** → 공개 버킷, 코드에만 있는 크기 검사 → **버킷 비공개, 읽기는 짧은 서명 주소, 크기 한도는 버킷 설정에도.**
27. ★★ **화면 이동마다 느리다** → 매번 Auth 서버를 왕복해 사용자를 확인했다 → **JWT 서명 키를 비대칭(ES256)으로 바꾸고 `getClaims()`로 로컬 검증. 세션 조회는 요청당 한 번.**
28. ★★ **pg_cron이 부른 크론이 405로 실패한다 / 비밀 검사가 비어 있을 위험** → `net.http_post`는 POST, Vercel 크론은 GET. 비밀 환경변수가 비면 `Bearer undefined`가 통과할 수 있다 → **크론 주소는 GET·POST 둘 다 받고, 비밀이 비어 있으면 거부(`if (!secret || …)`)하는 공통 껍데기 하나로.**
29. ★★ **동기화가 중간에 실패하면 일정이 사라진다** → 지우기를 먼저 했다 → **넣기·고치기 먼저, 지우기는 마지막. 기간 일정은 겹침 조건(`시작 < to and 끝 > from`)으로 찾는다. 원자성이 필요한 일은 SQL 함수 하나로.**
30. ★★ **같은 계정으로 여러 번 로그인하는 테스트가 갑자기 실패한다** → Auth의 로그인 횟수 제한 → **테스트에서는 세션을 한 번 받아 다시 쓴다.**

## 4. Vercel·Next.js

31. ★★★ **큰 파일을 붙여 보내면 아무 일도 안 일어난다(안내 없는 500)** → 서버 액션 본문 한도(4MB)·Vercel 요청 한도(4.5MB)에서 잘린다. 한도를 올려도 소용없다 → **서명 업로드 주소로 브라우저가 Supabase에 바로 올리고, 폼에는 경로만. 파일을 고르는 순간 크기 검사.**
32. ★★★ **로컬에서는 되는데 운영에서만 서식·글꼴 파일이 없다** → 실행 중에 읽는 파일이 서버리스 묶음에 안 들어갔다 → **`next.config`의 `outputFileTracingIncludes`에 등록하고 E2E로 확인.**
33. ★★★ **생성 도중 함수가 죽는다** → 재시도 예산(호출 제한 × 횟수)이 함수 최대 실행 시간보다 컸다 → **`maxDuration` > 호출당 제한 × 최대 시도 수. 거꾸로 호출 제한을 역산한다.**
34. ★★★ **서울 Supabase인데 응답이 느리다** → Vercel 함수 기본 지역이 미국 → **`vercel.json`에 `"regions": ["icn1"]`.**
35. ★★★ **푸시를 보내는 동안 응답이 늦다 / 날씨 API가 홈 화면을 붙잡는다** → 부가 작업을 응답 전에 기다렸다 → **알림·기록은 `after()`로 응답 뒤에. 외부 부가 정보는 Suspense로 떼고, 캐시하되 실패는 캐시하지 않는다.**
36. ★★★ **로그인이 풀린 뒤 「파일 받기」가 로그인 HTML을 저장한다 / AI 답이 조용히 사라진다 / 리디렉트 무한 반복** → 프록시가 화면 안 요청까지 로그인 페이지로 보냈다. 프로필이 없을 때 프록시와 페이지가 서로 다른 곳으로 보냈다 → **화면 안 요청(`sec-fetch-mode`가 navigate 아님, RSC·서버 액션 아님)에는 401 JSON. 프로필 문제는 로그아웃시킨 뒤 로그인으로.**
37. ★★★ **운영에서만 오류 문구가 영어 일반 메시지로 가려진다** → 운영 빌드는 서버 액션이 던진 오류 메시지를 숨긴다 → **서버 액션은 던지지 말고 `{ error }`를 돌려준다.**
38. ★★★ **지운 대화가 다시 보인다 / 로그아웃 뒤 다음 사람에게 앞사람 화면이 남는다** → 클라이언트 라우터 캐시 → **바꾸는 액션 뒤 `revalidatePath`, 대화 화면은 prefetch 끄기, 로그아웃은 전체 새로고침 이동.**
39. ★★ **새로 만든 계정이 로그인 목록에 안 보인다** → 로그인 페이지가 빌드 때 정적으로 굳었다. 스크립트로는 캐시를 비울 수 없다 → **로그인 페이지는 동적으로, 명단 캐시는 짧게(5분), 서버가 이름으로 직접 찾아 맞춘다.**
40. ★★ **순수 함수 테스트가 import만 해도 죽는다** → `server-only` 파일을 함께 들여왔다 → **순수 논리(`x.ts`)와 서버 코드(`x-repo.ts`)를 파일로 나눈다.**
41. ★★★ **AI가 쓴 Next.js 코드가 이 버전에서 안 맞는다** → 프레임워크가 학습 데이터보다 새롭다(예: 16에서 `middleware` → `proxy.ts`) → **코드 쓰기 전에 설치된 버전의 공식 문서를 읽으라는 규칙을 `AGENTS.md`에.**
42. ★★★ **교실 칠판 10대가 3초마다 묻는 것만으로 Vercel 무료 한도를 넘겨 계정이 멈췄다** → 호출 수 = 기기 수 × (86,400 ÷ 간격). 46대면 하루 130만 번 → **화면이 비면 15초, 밤·주말은 60초로 늦추고, 급한 소식은 웹푸시·실시간 채널로 깨운다. 몇 주씩 켜 두는 화면은 배포 id가 바뀌면 조용할 때 스스로 새로고침.**
43. ★★ **크론·웹훅·키오스크 화면이 로그인으로 튕긴다** → 프록시가 모든 경로를 검사 → **제외 목록에 명시하고, 그 경로가 비밀·토큰을 직접 검사한다.**

## 9. 테스트·배포

79. ★★★ **테스트가 운영 시간표를 실제로 바꾸고 운영 설정을 지운다** → 테스트가 운영 Supabase에 붙었다 → **시험용 Supabase를 따로 쓴다. 어쩔 수 없이 운영에 붙는 테스트는 명시적 허용 변수가 있을 때만, 설정은 저장했다가 복원, 정리는 실패해도 돌게, 순차 실행(`workers: 1`).**
80. ★★★ **미리보기 배포에서 시험했는데 실제 선생님들께 알림이 갔다** → 미리보기도 같은 운영 DB를 썼다 → **운영이 아닌 배포(`VERCEL_ENV !== "production"`)에서는 한 사람에게만, 못 찾으면 아무에게도.**
81. ★★ **테스트는 늘 통과하는데 실제로는 아무것도 확인하지 못했다** → 캐시 함수가 테스트 환경에서 던져 다른 경로를 탔다 → **목(mock)이 실제로 불렸는지까지 단언. 픽스처가 그 경로를 정말 타는지 확인.**
82. ★ **린트 오류 수만 건 / 운영 E2E 시간 초과 / 주말에 캡처가 빈 화면** → 작업 사본 폴더까지 린트했다. 서버 콜드 스타트. 주말엔 시간표가 비어 있다 → **린트 무시 목록 정리, 운영 E2E는 대기 시간·재시도 1회, 날짜를 고정해 시험.**

## 10. 바이브코딩 작업 방식

83. ★★★ **기능이 쌓이면 서로 어긋나는 버그가 숨어든다** → 기능별로만 만들고 전체를 보지 않았다 → **설계 문서(합의한 결정 표, 범위 밖 목록) → 단계 계획(실패하는 테스트부터) → 구현 → 리뷰 목록 → 병합. 기능 몇 개마다 전수 점검(원본 학교는 한 번에 16건 발견).**
84. ★★★ **다음 세션의 AI가 같은 함정을 되밟는다 / 문서와 코드가 어긋난다** → 「왜」가 기록되지 않았다 → **운영 문서와 커밋 본문에 증상·원인·이유를 적는다. 느슨해지면 안 되는 규칙은 `AGENTS.md`에 적고 테스트로 지킨다. 기능을 바꾸면 설계 문서도 같이 고친다.**
85. ★★ **AI가 제안한 코드가 틀렸다 / 마음에 안 들어 되돌렸더니 검증된 로직까지 날아갔다** → 확인 없이 받아들였다. 로직과 화면이 한 덩어리였다 → **외부 제안은 공식 문서로 확인된 것만. 로직과 화면을 나눠 두고 되돌릴 때는 화면만. 선생님들이 이미 쓰던 앱을 옮길 때는 화면 구조를 그대로.**
