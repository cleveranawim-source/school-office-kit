# 뼈대 설계 — 1단계

모든 모듈이 올라앉을 공통 바탕이다. 원본 학교의 「AI 교무실」의 구조를 일반화했다. 이 문서는 **무엇을 어떤 모양으로** 만들지를 말하고, 코드는 에이전트가 이 학교에 맞게 새로 쓴다.

> 라이브러리 버전은 계속 바뀐다. 에이전트는 코드를 쓰기 전에 그 버전의 공식 문서를 확인한다(Next.js는 버전마다 파일 규칙이 바뀐다. 예: 16에서 `middleware.ts` → `proxy.ts`). Next 16의 `next dev`는 `AGENTS.md`에 자기 안내 블록을 넣는다. 지워도 다시 넣으므로 그대로 함께 커밋한다.

## 1. 기술 조합

| 층 | 쓰는 것 | 왜 |
|---|---|---|
| 화면·서버 | Next.js(App Router, TypeScript) + Tailwind | 화면과 서버 코드를 한 저장소에. Vercel과 궁합 |
| 데이터·로그인·파일 | Supabase(Postgres, Auth, Storage, pg_cron) | **행 단위 권한(RLS)**으로 「서버가 데이터를 지킨다」를 데이터베이스에서 강제. 서울 지역 |
| 배포 | Vercel(서울 `icn1`) | GitHub에 올리면 자동 배포 |
| 알림 | 웹푸시(VAPID) + 서비스 워커 | 앱 설치 없이 휴대폰 알림 |
| AI(선택) | Anthropic 또는 OpenAI API | `07-AI도우미.md` |

원칙: **브라우저에는 그 사람이 볼 수 있는 것만 간다.** 권한 검사는 화면이 아니라 서버와 데이터베이스가 한다.

## 2. 계정·로그인

교직원만 계정이 있다. 학생·학부모는 계정 없이 다른 창구(카카오 채널 봇, 로그인 없는 학생용 보기 등)로 들어온다.

### 로그인 방식 — 인터뷰에서 고른다

| 방식 | 좋은 점 | 조심할 점 |
|---|---|---|
| **A. 이름 + 비밀번호** (원본 학교 방식) | 교사가 이메일을 몰라도 됨. 시스템이 `t{번호}@<학교약칭>.local` 같은 가짜 이메일을 만들어 Supabase Auth에 넣는다 | 계정 생성·초기 비밀번호 배부를 운영자가 해야 함 |
| **B. 학교 구글(또는 MS) 계정** | 비밀번호 관리 불필요 | 모든 교직원이 학교 계정을 갖고 있어야 함. 허용 도메인 제한 필수 |

### 공통 규칙

- **공개 가입을 끈다**(Supabase Auth 「새 사용자 가입 허용」 끄기). 계정은 운영자만 만든다.
- 교직원 표 `profiles`: `id`(Auth 사용자), `name`, `department`, `role`(`admin`/`teacher`), `active`, `must_change_password`. 휴직을 두면 `on_leave`.
- 역할은 **관리자/교사 둘**로 시작한다. 담임·부서·교과 같은 것은 역할이 아니라 별도 표(담임 배정, 조직표)로 표현한다.
- A 방식이면:
  - 초기 비밀번호는 **사람마다 다른 무작위 값**(헷갈리는 글자 0·O·1·l·I 빼기)으로 만들어 CSV로 배부하고, 배부 뒤 파일을 지운다.
  - 첫 로그인 때 **비밀번호 변경을 강제**한다.
  - 이름 입력은 NFC로 정규화하고 공백을 무시한다(`06-함정노트.md`). 동명이인은 고르게 한다.
  - **틀린 횟수를 제한한다**: (사람 + 접속 주소)마다, 접속 주소마다 따로 센다. 기록 표와 함수는 서버만(`05-보안기준선.md` F절).
  - 로그인 화면에 전 교직원 이름 목록을 내려보내면, 로그인 안 한 사람도 교직원 명단을 볼 수 있다. 편의와 노출을 저울질해 학교와 정한다(대안: 두 글자 이상 쳐야 서버에서 찾아 주기).
- **비활성화**: 퇴직·전출 교사는 지우지 않고 `active=false` → **Auth 사용자 차단(`ban_duration`)도 함께** → 그 사람의 푸시 구독 삭제. 차단하지 않으면 이미 받은 토큰이 끝날 때까지 쓸 수 있다. `profiles`를 먼저 바꾼다(`05-보안기준선.md` F절). 단체 발송은 `active`인 사람에게만.
- **휴직**(두면): 정해 둔 곳만 열고 나머지는 앱·DB가 함께 막는다(`05-보안기준선.md` F절). 휴직·복직·교사 추가는 관리 화면에서.
- 관리자는 두 명 이상. 자기 자신은 비활성화하거나 관리자에서 뺄 수 없게 한다.

## 3. 권한 — 세 겹으로 지킨다

1. **서버 진입부**: 모든 서버 액션·API 첫 줄에서 세션을 확인하는 공통 함수를 부른다(아래 표).
2. **데이터베이스 RLS**: 모든 표에 RLS를 켜고 익명(anon) 권한을 회수한다. 모든 표에 「교직원만」 제한 정책을 덧댄다. 정책 패턴은 `05-보안기준선.md` B절.
3. **키 두 종류를 구분**:
   - 공개 키(publishable) + 로그인 쿠키 → RLS가 적용되는 일반 클라이언트. 기본은 이것.
   - 시크릿 키 → RLS를 건너뛴다. **서버 전용 파일**(`server-only`)에서만, 권한 확인을 마친 뒤에만, 크론·스크립트·쓰기 정책을 일부러 막아 둔 표에만 쓴다.

### 세션 함수 — `lib/auth/session.ts` 한 파일

| 함수 | 돌려주는 것 | 쓰는 곳 |
|---|---|---|
| `getSessionProfile()` | 내 프로필. 로그인 안 했거나 **비활성·휴직이면 null** | API·파일 내려받기(null이면 401), 화면 일부 |
| `getSessionProfileAny()` | 휴직도 그대로 돌려준다(비활성은 null) | 휴직에게 열 곳만 |
| `requireProfile(opts)` | 화면·서버 액션의 첫 줄. 없거나 비활성이면 로그아웃 → 로그인 화면, 비밀번호를 바꿔야 하면 그 화면, 휴직이면 휴직 첫 화면 | 기본. 예외는 `allowPasswordChange`(비밀번호 바꾸기 화면)·`allowOnLeave`(휴직에게 열 곳) |
| `requireAdmin()` | `requireProfile()` + 관리자가 아니면 홈으로 | 관리 화면·관리 동작 |

- 새 기능은 기본 함수만 쓰면 휴직·비활성에게 저절로 닫힌다. 여는 쪽을 따로 표시하게 만든다.
- 요청 하나에서 레이아웃·페이지가 여러 번 불러도 **한 번만 조회**한다(React `cache`).
- 토큰은 `getClaims()`로 로컬에서 확인하고(ES256, 함정 27), 프로필은 RLS가 본인 행만 돌려주므로 토큰의 `sub`로 읽는다.

### 브라우저용 Supabase 클라이언트는 두지 않는다

화면은 서버 컴포넌트·서버 액션·API로만 데이터를 받는다. 브라우저에 Supabase 클라이언트가 없으면 「화면에서 바로 표를 읽는」 길이 처음부터 없고, 무엇이 브라우저로 가는지 서버 코드만 보면 안다.

- 파일 올리기는 서버가 준 서명된 업로드 주소로 브라우저가 직접 올린다(5절 「파일 업로드」). 클라이언트 없이 된다.
- 예외: 로그인 없는 실시간 화면(교실 칠판)이 공개 키로 실시간 채널의 깨우기 신호만 듣는 것. 표는 읽지 않는다(`05-보안기준선.md` E절).

## 4. proxy — 모든 요청의 길목

Next 16부터 파일 이름이 `proxy.ts`(함수 이름 `proxy`)다. 그 전 버전은 `middleware.ts`. 하는 일은 다섯 가지다.

1. **세션 갱신**: 공개 키 클라이언트로 `getClaims()`를 부른다. 토큰이 끝났을 때만 Auth 서버에 새 토큰을 받으러 가고, 바뀐 쿠키를 요청과 응답 둘 다에 싣는다.
2. **동시 갱신 충돌(409) 되살리기**: 토큰이 끝난 뒤 홈을 열면 메뉴 링크 미리 받기로 요청 스무 개가 한꺼번에 오고, 저마다 같은 refresh 토큰으로 새 토큰을 받으려 한다. Supabase는 하나만 받아 주고 나머지에 409(`code: "conflict"`)를 돌려준다. Auth 라이브러리는 이를 죽은 세션으로 보고 쿠키를 지워, 선생님이 로그인 화면으로 튕긴다.
   - 충돌이면 그 시도가 지운 쿠키를 처음 것으로 되돌리고 0.4초 뒤 다시 묻는다(최대 두 번). 재사용 간격 안이라 다른 요청이 받은 새 토큰으로 이어진다.
   - 끝까지 충돌이어도 쿠키를 지우지 않는다. 다른 오류(refresh 토큰이 정말 없음 등)는 그대로 로그아웃.
   - 이 흐름은 순수 함수로 떼어 단위 테스트한다(시도·되돌리기·기다리기를 인자로).
3. **로그인 안 한 요청**: 화면 이동이면 `/login`으로 보낸다. 화면 안에서 부른 fetch(파일 내려받기, AI 대화)에는 401을 준다 — 따라가면 로그인 HTML이 파일로 저장되거나 답이 조용히 사라진다(함정 36). Next 자체의 요청(`rsc`·`next-action` 헤더)은 Next가 스스로 처리하므로 뺀다. 로그인한 사람이 `/login`에 오면 홈으로.
4. **공개 경로 목록**: 로그인 없이 지나가는 경로를 **한 곳에** 적는다(함정 43). 정적 파일·`sw.js`·매니페스트, 크론(`/api/cron`), 외부 봇, CSP 보고, 교실 칠판 화면·API, 학생용 보기, 로그인 화면. 목록에 넣는 경로는 그 안에서 열쇠를 직접 검사한다. 새 경로를 넣을 때는 `05-보안기준선.md` E절을 먼저 본다.
5. **CSP nonce**: 요청마다 새 nonce를 만들어 요청 헤더(`x-nonce`와 CSP)와 응답 헤더에 싣는다. 정책 만들기는 순수 함수 한 파일(`lib/security/csp.ts`)에. 다른 곳에서 같은 이름의 CSP 헤더를 붙이지 않는다(`05-보안기준선.md` C절).

## 5. 공통 부품

### 설정 표 (키-값)

`settings(key, value jsonb, updated_at)` 하나에 학기마다 바뀌는 값(교시 시간, 외부 링크, 안내문, 크론 실행 기록)을 둔다. 읽을 때 모양을 검사하고, 틀리면 코드 기본값을 쓴다. 관리자만 읽고 쓰되, 교사도 봐야 하는 키(교시 시간)만 따로 연다.

### 학교 설정 파일

학교 이름(한글·영문), 약칭, 대표 색, 학년 수, 교시 기본값, 근무 시간 기본값, 사이트 주소는 **설정 파일 한 곳**(예: `school.config.ts`)에 모은다. 원본 학교는 학교 이름이 15곳, 색이 3곳, 학년 수가 여러 화면에 흩어져 있었다.

### 날짜·시간

- 서버(Vercel)는 UTC로 돈다. 「오늘」은 항상 서울 기준 함수 하나(`todayInSeoul()`)로 구한다.
- 하루 범위 질의는 `YYYY-MM-DDT00:00:00+09:00`처럼 시간대를 붙여 쓴다.
- 크론 식은 **UTC**다. 서울 07:50 = UTC 22:50 전날.
- UTC 자정 경계(서울 오전 9시 직전)를 테스트로 확인한다.

### 크론 — 두 갈래

| 용도 | 어디서 | 예 |
|---|---|---|
| 정확한 시각·자주 | Supabase `pg_cron` + `pg_net`이 우리 API를 부름 | 아침 7:50 알림, 1분마다 도는 일 |
| 하루 한 번 청소 | Vercel 크론(`vercel.json`) | 새벽 3시 오래된 공지 지우기 |

- **공통 껍데기 하나**로 모든 크론 주소를 감싼다(`cronRoute(이름, 할 일)`):
  - 비밀(`CRON_SECRET`)이 비어 있으면 거부하고, `Authorization: Bearer <CRON_SECRET>`을 `secretEquals`로 비교한다(`05-보안기준선.md` C절).
  - Vercel 크론은 GET, `pg_net`은 POST로 부르므로 둘 다 붙인다(함정 28).
  - 결과는 JSON으로, 터진 것은 기록한 뒤 500으로 돌려준다.
- 크론 주소는 로그인 리디렉트 대상에서 뺀다(4절 공개 경로 목록).
- **멱등**: 「오늘 보냈음」을 **보내기 전에** 조건부로 적어서, 두 번 불려도 한 번만 보낸다.
- **1분 틱 하나에 여러 일을 얹는다.** 일마다 `pg_cron` 작업을 만들면 호출 수가 늘어난다. 틱 안에서 일들이 서로를 막지 않게 `Promise.allSettled`로 함께 돌리고, 곁일이 실패하면 결과에 오류 글로 남기고, 본일이 실패하면 곁일이 끝난 뒤 다시 던진다(크론 기록은 실패로). 하루 한 번 할 일은 틱 안에서 멱등 키로 거른다.
- 서울 근무 시간은 UTC로 날짜를 넘으므로 `pg_cron` 일정을 둘로 나눈다. 예: 서울 평일 08:00~17:59 = `* 23 * * 0-4`(UTC 전날 23시) + `* 0-8 * * 1-5`(함정 14).
- **미리 보기**: `?dry=1`(비밀 필요)이면 보내지 않고 대상만 돌려준다. 한 사람에게만 보내 보는 시험(`&user=`)은 멱등 기록을 쓰지 않는다.
- 결과를 설정 표에 남겨 관리자 화면에서 볼 수 있게 한다.
- `pg_cron` 등록 SQL도 저장소(마이그레이션 또는 운영 문서)에 남긴다. 대시보드에서 손으로만 등록하면 다음 사람이 모른다.

### 웹푸시

- 표 `push_subscriptions`(endpoint 유일, 키, 실패 횟수). 404·410이면 구독 삭제, 그 밖의 실패는 횟수를 세다가 지운다. 발송마다 제한 시간(15초).
- **시험 잠금**: 설정 하나로 「지정한 한 사람에게만」 보내는 모드. 미리보기 배포에서는 항상 시험 잠금.
- 서비스 워커는 화면을 캐시하지 않고(`no-cache`), 새 버전으로 바로 갈아탄다.
- 알림을 누르면 그 화면으로 간다. 아이폰은 방식이 달라 따로 처리한다(`06-함정노트.md`).

### 개인 알림은 한 곳으로

- 사람에게 가는 알림은 모두 함수 하나(`notifyUsers(받는 사람들, 내용)`)를 지난다. 그 안에서 먼저 비활성·휴직을 빼고 시험 잠금을 적용한 뒤, 남은 사람의 알림함(앱 안 기록)에 적고 푸시를 보낸다. 모듈마다 따로 보내면 하나쯤 휴직 선생님께 간다.
- 「/<메뉴>/<id>」처럼 특정 글을 가리키는 알림을 새로 만들면, 그 표에 **지우기 트리거**도 건다: 글을 지우면 그 글을 가리키는 알림함 글도 지운다. 지운 글의 제목이 알림함에 남지 않는다.
- 알림 내용에 토큰·내부 id·사유를 싣지 않는다(`05-보안기준선.md` E·G절).

### 기능 문 — 관리자에게 먼저 보이기

- 새 기능은 상수 하나(`<기능>_ADMIN_ONLY = true`)로 관리자에게만 먼저 연다. 메뉴·화면·서버 동작·AI 도구·알림이 **모두 이 값 하나**를 본다.
- 미리 보기 동안에는 학생이 보는 출력(교실 칠판)과 단체 알림을 보내지 않는다.
- 공개는 값만 `false`로 바꾼다. 언제 누가 정했는지 `progress.md`에 적는다.

### 파일 업로드

- 파일을 서버 액션으로 보내지 않는다(본문 한도에 걸린다). 서버가 **서명된 업로드 주소**를 주고, 브라우저가 Supabase에 바로 올린다.
- 경로는 서버가 정한다(`drafts/<사용자>/<임시id>/…`). 저장할 때 「내 임시 자리인지」를 **경로 검사 함수**로 보고(`05-보안기준선.md` D절), **실제 크기**를 다시 확인한 뒤 최종 자리로 옮긴다.
- 버킷은 모두 비공개. 받을 때는 권한 확인 → 60초짜리 서명 주소로 보낸다.
- 크기 한도는 코드와 **버킷 설정 둘 다**에 건다.

### 화면 틀

- 넓은 화면은 왼쪽 메뉴, 휴대폰은 아래 탭 5개(홈·자주 쓰는 것 셋·더보기).
- 메뉴 구성은 **파일 하나**(모듈 목록: 경로·이름·설명·아이콘·묶음·관리자 전용 여부)에서 만든다. 기능 문 상수도 여기서 쓴다.
- 디자인 값(색·모서리·그림자)은 CSS 토큰 한 곳에. 입력칸 글자는 16px 이상(아이폰 자동 확대 방지).
- PWA 매니페스트와 아이콘(192·512·maskable, 애플 아이콘).

## 6. 테스트 세 층

| 층 | 무엇을 | 언제 |
|---|---|---|
| 단위(vitest) | 순수 로직: 날짜, 이름 맞추기, 배달 시각, 권한 함수, 메뉴 구성, 경로 검사, 비밀 비교, CSP 만들기, 동시 갱신 되살리기, 경로별 보안 헤더 | 매번 |
| RLS(vitest + 실제 Supabase) | 교사 계정·관리자 계정으로 로그인해 「볼 수 있다 / 없다」를 둘 다 확인 | 표·정책을 바꿀 때마다 |
| 화면(Playwright, 휴대폰 크기) | 로그인, 첫 로그인 비밀번호 변경, 교사에게 관리 메뉴 없음, 가로 스크롤 없음, 다른 사이트에서 감싸기 차단 | 단계 관문 |

- RLS·화면 테스트는 **운영과 다른 시험용 Supabase 프로젝트**에 붙인다. 원본 학교는 운영에 붙여서 시험 잠금 같은 안전장치가 따로 필요해졌다.
- **RLS 테스트는 파일을 하나씩 돌린다**(vitest `--no-file-parallelism`). 한꺼번에 로그인하면 Auth 로그인 횟수 제한에 걸린다(함정 30).
- **「교직원만」 테스트 파일 하나**를 둔다: `profiles` 행이 없는 계정으로 모든 표 0행, 휴직·비활성 계정, 뷰 고치기·지우기 거부. 새 표를 만들면 그 목록에 더한다(`05-보안기준선.md` B절).
- 서버 액션만 막던 규칙은 교사 토큰으로 직접 넣어 거부되는지 RLS 테스트에서 본다.
- 순수 로직은 서버 코드와 파일을 나눠야 단위 테스트가 들여올 수 있다(함정 40).
- 화면 테스트가 만드는 자료는 표시(예: 이름 앞에 「E2E 」)를 붙여 넣고 시험마다 지운다.
- 배포된 운영 주소에 돌리는 화면 테스트는 따로 설정 파일을 두고, 명시적 환경변수를 켤 때만 돈다. 배포 직후에는 로그인 없이 도는 것(보안 헤더·없는 주소)부터.
- 지켜야 하는 규칙(「토큰을 알림에 싣지 않는다」 등)은 말로만 적지 말고 테스트로 묶는다.
- AI 도우미는 넷째 층으로 점검 세트를 둔다(`07-AI도우미.md` 6절).

## 7. 환경변수 (이름만)

`.env.example`에 **전부** 적어 둔다(값은 비움). `gate.mjs`가 코드가 쓰는 이름과 맞춰 본다.

| 이름 | 용도 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 주소 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 공개 키 |
| `SUPABASE_SECRET_KEY` | 시크릿 키(서버 전용) |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | 웹푸시 |
| `CRON_SECRET` | 크론 인증 |
| `NEXT_PUBLIC_BASE_URL` | 사이트 주소 |
| `ANTHROPIC_API_KEY` 또는 `OPENAI_API_KEY`, 모델 이름 | AI 도우미(선택) |
| 공유 드라이브 열쇠(예: `GOOGLE_DRIVE_KEY`) | AI 공유 드라이브 읽기(선택, 값은 저장소 밖 JSON) |
| `NEIS_KEY` | 나이스 공개 API(급식 등, 선택) |
| `TEST_TEACHER_PASSWORD`, `TEST_ADMIN_PASSWORD` | 테스트 계정 |
| `E2E_BASE_URL` | 배포 주소에 화면 테스트를 돌릴 때 |

`NEXT_PUBLIC_`이 붙은 값은 브라우저로 간다. 비밀 값에는 절대 붙이지 않는다.

## 9. 문서

규칙·기능별 결정·고치는 순서를 어느 문서에 둘지는 `08-인수인계.md` 「문서 구조」를 따른다. 1단계에서 그 뼈대 파일을 함께 만든다.

## 1단계 관문

- [ ] 공개 가입이 꺼져 있다
- [ ] 교사 계정·관리자 계정으로 로그인되고, 첫 로그인 때 비밀번호 변경이 강제된다
- [ ] 비밀번호를 여러 번 틀리면 막힌다
- [ ] RLS 테스트: 교사는 자기 프로필만 보고, 역할을 바꾸지 못하고, 관리자 전용 설정을 못 본다
- [ ] 「교직원만」 테스트: `profiles` 행이 없는 계정은 모든 표에서 0행이다
- [ ] 로그인 안 한 상태에서 데이터 API를 직접 불러도 아무것도 안 나온다(익명 회수 확인)
- [ ] 비활성화한 계정은 다시 로그인되지 않는다(Auth 차단 확인)
- [ ] 휴대폰(아이폰·안드로이드 각 1대)에서 로그인 → 홈 화면에 추가 → 다시 열기가 된다
- [ ] 로그인 토큰이 끝난 뒤(1시간) 홈을 열어도 로그인 화면으로 튕기지 않는다
- [ ] 교사 계정에는 관리 메뉴가 보이지 않는다
- [ ] 폭 390px에서 가로 스크롤이 없다
- [ ] 보안 헤더와 CSP(Report-Only)가 붙는다
- [ ] `.env*`가 커밋되지 않았다
- [ ] `gate.mjs`에 ❌가 없다
