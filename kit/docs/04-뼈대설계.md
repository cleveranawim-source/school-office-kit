# 뼈대 설계 — 1단계

모든 모듈이 올라앉을 공통 바탕이다. 원본 학교의 「AI 교무실」의 구조를 일반화했다. 이 문서는 **무엇을 어떤 모양으로** 만들지를 말하고, 코드는 에이전트가 이 학교에 맞게 새로 쓴다.

> 라이브러리 버전은 계속 바뀐다. 에이전트는 코드를 쓰기 전에 그 버전의 공식 문서를 확인한다(Next.js는 버전마다 파일 규칙이 바뀐다. 예: 16에서 `middleware.ts` → `proxy.ts`).

## 1. 기술 조합

| 층 | 쓰는 것 | 왜 |
|---|---|---|
| 화면·서버 | Next.js(App Router, TypeScript) + Tailwind | 화면과 서버 코드를 한 저장소에. Vercel과 궁합 |
| 데이터·로그인·파일 | Supabase(Postgres, Auth, Storage, pg_cron) | **행 단위 권한(RLS)**으로 「서버가 데이터를 지킨다」를 데이터베이스에서 강제. 서울 지역 |
| 배포 | Vercel(서울 `icn1`) | GitHub에 올리면 자동 배포 |
| 알림 | 웹푸시(VAPID) + 서비스 워커 | 앱 설치 없이 휴대폰 알림 |
| AI(선택) | Anthropic 또는 OpenAI API | `07-AI도우미.md` |

원칙: **브라우저에는 그 사람이 볼 수 있는 것만 간다.** 권한 검사는 화면이 아니라 서버와 데이터베이스가 한다.

## 2. 계정·로그인

교직원만 계정이 있다. 학생·학부모는 계정 없이 다른 창구(카카오 채널 봇 등)로 들어온다.

### 로그인 방식 — 인터뷰에서 고른다

| 방식 | 좋은 점 | 조심할 점 |
|---|---|---|
| **A. 이름 + 비밀번호** (원본 학교 방식) | 교사가 이메일을 몰라도 됨. 시스템이 `t{번호}@<학교약칭>.local` 같은 가짜 이메일을 만들어 Supabase Auth에 넣는다 | 계정 생성·초기 비밀번호 배부를 운영자가 해야 함 |
| **B. 학교 구글(또는 MS) 계정** | 비밀번호 관리 불필요 | 모든 교직원이 학교 계정을 갖고 있어야 함. 허용 도메인 제한 필수 |

### 공통 규칙

- **공개 가입을 끈다**(Supabase Auth 「새 사용자 가입 허용」 끄기). 계정은 운영자만 만든다.
- 교직원 표 `profiles`: `id`(Auth 사용자), `name`, `department`, `role`(`admin`/`teacher`), `active`, `must_change_password`.
- 역할은 **관리자/교사 둘**로 시작한다. 담임·부서·교과 같은 것은 역할이 아니라 별도 표(담임 배정, 조직표)로 표현한다.
- A 방식이면:
  - 초기 비밀번호는 **사람마다 다른 무작위 값**(헷갈리는 글자 0·O·1·l·I 빼기)으로 만들어 CSV로 배부하고, 배부 뒤 파일을 지운다.
  - 첫 로그인 때 **비밀번호 변경을 강제**한다.
  - 이름 입력은 NFC로 정규화하고 공백을 무시한다(`06-함정노트.md`). 동명이인은 고르게 한다.
  - 로그인 화면에 전 교직원 이름 목록을 내려보내면, 로그인 안 한 사람도 교직원 명단을 볼 수 있다. 편의와 노출을 저울질해 학교와 정한다(대안: 두 글자 이상 쳐야 서버에서 찾아 주기).
- **비활성화**: 퇴직·전출 교사는 지우지 않고 `active=false` → 로그인 차단 → 그 사람의 푸시 구독 삭제. 단체 발송은 `active`인 사람에게만.
- 관리자는 두 명 이상.

## 3. 권한 — 세 겹으로 지킨다

1. **서버 진입부**: 모든 서버 액션·API 첫 줄에서 세션을 확인하는 공통 함수(`requireProfile()`, `requireAdmin()`)를 부른다. 비활성 계정이면 로그아웃시키고, 비밀번호 변경이 필요하면 그 화면으로 보낸다.
2. **데이터베이스 RLS**: 모든 표에 RLS를 켜고 익명(anon) 권한을 회수한다. 정책 패턴은 `05-보안기준선.md`.
3. **키 두 종류를 구분**:
   - 공개 키(publishable) + 로그인 쿠키 → RLS가 적용되는 일반 클라이언트. 기본은 이것.
   - 시크릿 키 → RLS를 건너뛴다. **서버 전용 파일**(`server-only`)에서만, 권한 확인을 마친 뒤에만, 크론·스크립트·쓰기 정책을 일부러 막아 둔 표에만 쓴다.

## 4. 공통 부품

### 설정 표 (키-값)

`settings(key, value jsonb, updated_at)` 하나에 학기마다 바뀌는 값(교시 시간, 외부 링크, 안내문, 크론 실행 기록)을 둔다. 읽을 때 모양을 검사하고, 틀리면 코드 기본값을 쓴다. 관리자만 읽고 쓰되, 교사도 봐야 하는 키(교시 시간)만 따로 연다.

### 학교 설정 파일

학교 이름(한글·영문), 약칭, 대표 색, 학년 수, 교시 기본값, 근무 시간 기본값, 사이트 주소는 **설정 파일 한 곳**(예: `school.config.ts`)에 모은다. 원본 학교는 학교 이름이 15곳, 색이 3곳, 학년 수가 여러 화면에 흩어져 있었다.

### 날짜·시간

- 서버(Vercel)는 UTC로 돈다. 「오늘」은 항상 서울 기준 함수 하나(`todayInSeoul()`)로 구한다.
- 하루 범위 질의는 `YYYY-MM-DDT00:00:00+09:00`처럼 시간대를 붙여 쓴다.
- 크론 식은 **UTC**다. 서울 07:50 = UTC 22:50 전날.
- UTC 자정 경계(서울 오전 9시 직전)를 테스트로 확인한다.

### 크론 — 두 갈래

| 용도 | 어디서 | 예 |
|---|---|---|
| 정확한 시각·자주 | Supabase `pg_cron` + `pg_net`이 우리 API를 부름 | 아침 7:50 알림, 1분마다 도는 일 |
| 하루 한 번 청소 | Vercel 크론(`vercel.json`) | 새벽 3시 오래된 공지 지우기 |

- 크론 API는 `Authorization: Bearer <CRON_SECRET>`을 확인하고, 로그인 리디렉트 대상에서 뺀다.
- **멱등**: 「오늘 보냈음」을 **보내기 전에** 조건부로 적어서, 두 번 불려도 한 번만 보낸다.
- 결과를 설정 표에 남겨 관리자 화면에서 볼 수 있게 한다.
- `pg_cron` 등록 SQL도 저장소(마이그레이션 또는 운영 문서)에 남긴다. 대시보드에서 손으로만 등록하면 다음 사람이 모른다.

### 웹푸시

- 표 `push_subscriptions`(endpoint 유일, 키, 실패 횟수). 404·410이면 구독 삭제, 그 밖의 실패는 횟수를 세다가 지운다. 발송마다 제한 시간(15초).
- **시험 잠금**: 설정 하나로 「지정한 한 사람에게만」 보내는 모드. 미리보기 배포에서는 항상 시험 잠금.
- 서비스 워커는 화면을 캐시하지 않고(`no-cache`), 새 버전으로 바로 갈아탄다.
- 알림을 누르면 그 화면으로 간다. 아이폰은 방식이 달라 따로 처리한다(`06-함정노트.md`).

### 파일 업로드

- 파일을 서버 액션으로 보내지 않는다(본문 한도에 걸린다). 서버가 **서명된 업로드 주소**를 주고, 브라우저가 Supabase에 바로 올린다.
- 경로는 서버가 정한다(`drafts/<사용자>/<임시id>/…`). 저장할 때 「내 임시 자리인지」와 **실제 크기**를 다시 확인한 뒤 최종 자리로 옮긴다.
- 버킷은 모두 비공개. 받을 때는 권한 확인 → 60초짜리 서명 주소로 보낸다.
- 크기 한도는 코드와 **버킷 설정 둘 다**에 건다.

### 로그인 만료 처리

화면 안에서 부르는 요청(파일 받기, AI 대화)은 로그인 페이지로 리디렉트하지 말고 401을 돌려준다. 리디렉트를 따라가면 로그인 화면 HTML이 파일로 저장되거나 AI 답이 사라진다.

### 화면 틀

- 넓은 화면은 왼쪽 메뉴, 휴대폰은 아래 탭 5개(홈·자주 쓰는 것 셋·더보기).
- 메뉴 구성은 **파일 하나**(모듈 목록: 경로·이름·설명·아이콘·묶음·관리자 전용 여부)에서 만든다.
- 디자인 값(색·모서리·그림자)은 CSS 토큰 한 곳에. 입력칸 글자는 16px 이상(아이폰 자동 확대 방지).
- PWA 매니페스트와 아이콘(192·512·maskable, 애플 아이콘).

## 5. 테스트 세 층

| 층 | 무엇을 | 언제 |
|---|---|---|
| 단위(vitest) | 순수 로직: 날짜, 이름 맞추기, 배달 시각, 권한 함수, 메뉴 구성 | 매번 |
| RLS(vitest + 실제 Supabase) | 교사 계정·관리자 계정으로 로그인해 「볼 수 있다 / 없다」를 둘 다 확인 | 표·정책을 바꿀 때마다 |
| 화면(Playwright, 휴대폰 크기) | 로그인, 첫 로그인 비밀번호 변경, 교사에게 관리 메뉴 없음, 가로 스크롤 없음 | 단계 관문 |

- RLS·화면 테스트는 **운영과 다른 시험용 Supabase 프로젝트**에 붙인다. 원본 학교는 운영에 붙여서 푸시 잠금 같은 안전장치가 따로 필요해졌다.
- 지켜야 하는 규칙(「토큰을 알림에 싣지 않는다」 등)은 말로만 적지 말고 테스트로 묶는다.

## 6. 환경변수 (이름만)

`.env.example`에 **전부** 적어 둔다(값은 비움).

| 이름 | 용도 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 주소 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 공개 키 |
| `SUPABASE_SECRET_KEY` | 시크릿 키(서버 전용) |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | 웹푸시 |
| `CRON_SECRET` | 크론 인증 |
| `NEXT_PUBLIC_BASE_URL` | 사이트 주소 |
| `ANTHROPIC_API_KEY` 또는 `OPENAI_API_KEY`, 모델 이름 | AI 도우미(선택) |
| `NEIS_KEY` | 나이스 공개 API(급식 등, 선택) |
| `TEST_TEACHER_PASSWORD`, `TEST_ADMIN_PASSWORD` | 테스트 계정 |

`NEXT_PUBLIC_`이 붙은 값은 브라우저로 간다. 비밀 값에는 절대 붙이지 않는다.

## 7. 스크립트

| 스크립트 | 하는 일 |
|---|---|
| 교직원 계정 만들기 | 명단(엑셀·CSV) → 계정 + 초기 비밀번호 CSV. `--dry-run`으로 먼저 보기 |
| 교직원 추가 | 명단 밖 인원(교장·보건 등)을 이름으로 |
| 관리자 지정 | 이름으로 |
| 테스트 계정 만들기 | 테스트교사·테스트관리자 |

명단 파일처럼 실명이 든 자료는 저장소에 커밋하지 않는다.

## 1단계 관문

- [ ] 공개 가입이 꺼져 있다
- [ ] 교사 계정·관리자 계정으로 로그인되고, 첫 로그인 때 비밀번호 변경이 강제된다
- [ ] RLS 테스트: 교사는 자기 프로필만 보고, 역할을 바꾸지 못하고, 관리자 전용 설정을 못 본다
- [ ] 로그인 안 한 상태에서 데이터 API를 직접 불러도 아무것도 안 나온다(익명 회수 확인)
- [ ] 휴대폰(아이폰·안드로이드 각 1대)에서 로그인 → 홈 화면에 추가 → 다시 열기가 된다
- [ ] 교사 계정에는 관리 메뉴가 보이지 않는다
- [ ] 폭 390px에서 가로 스크롤이 없다
- [ ] `.env*`가 커밋되지 않았다
