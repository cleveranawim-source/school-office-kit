# 보안 기준선

교직원 사이트는 교직원 명단, 담임 배정, 결석 사유(건강 정보), 업무 문서를 다룬다. 이 문서의 항목은 **선택이 아니다.** 각 단계 관문에서 해당 항목을 확인한다.

원본 학교의 「AI 교무실」에서 잘 된 패턴은 그대로 가져왔고, 운영하면서 발견한 빈틈은 「처음부터 이렇게」로 바꿔 적었다. `gate.mjs`가 코드로 알 수 있는 것은 자동으로 검사하고, 나머지는 이 문서의 체크 상자로 손으로 확인한다.

| 언제 | 볼 절 |
|---|---|
| 1단계(뼈대) | A, B, C, F |
| 파일을 다루는 단계 | D |
| 로그인 없는 화면, 바깥 서비스·AI가 바깥 주소를 읽는 일 | E |
| 학생·교사 개인 정보가 화면에 나오는 단계 | G |
| AI 도우미 | H, E |
| 매달 | I |

## A. 처음 설정 (1단계 전에)

- [ ] **Supabase Auth에서 공개 가입을 끈다.** 켜져 있으면 아무나 계정을 만들고, `로그인한 사람 누구나 읽기` 정책이 걸린 표를 직접 읽을 수 있다.
- [ ] Supabase JWT 서명 키를 **비대칭(ES256)** 으로 바꾼다(서버에서 로그인 확인을 왕복 없이 하려면 필요).
- [ ] 저장소 **비공개**, `.gitignore`에 `.env*`, `out/`(초기 비밀번호 CSV), 실명 명단 파일.
- [ ] 운영 Supabase와 **시험용 Supabase를 따로** 만든다. 테스트는 시험용에만 붙인다.
- [ ] AI 회사 콘솔에 월 지출 한도(또는 선불 충전으로 상한).
- [ ] 저장소의 보안 알림(GitHub Dependabot 등)을 켠다(E절 「바깥 코드」).

## B. 데이터베이스 권한 (RLS)

### 기본

- 모든 표: `enable row level security` + 익명(`anon`) 권한 회수.
- 「로그인한 사람 누구나」를 `using (true)`로 쓰지 말고, **활성 교직원인지 확인하는 함수**(`is_member()`: `profiles`에 내 행이 있고 `active`, 휴직을 두면 `not on_leave`도 — F절)를 쓴다. 공개 가입이 실수로 켜져도 막힌다.
- **「교직원만」 제한 정책을 모든 표에 덧댄다.** 표마다 읽기·쓰기 규칙이 흩어져 있으면 하나쯤 빠뜨린다. 안전망으로 같은 정책 하나를 모든 표에 건다.

  ```sql
  create policy members_only on public.<표> as restrictive for all to authenticated
    using (public.is_member()) with check (public.is_member());
  ```

  - `as restrictive`는 다른 정책과 「그리고」로 묶인다. 원래 규칙은 그대로 두고, 가입만 한 계정·비활성 계정·휴직 계정만 한 번 더 막는다.
  - 예외는 `profiles`(판별 함수가 읽는 표)와, 휴직 중에도 읽어야 하는 표의 **읽기**뿐이다. 그 표는 읽기를 휴직도 되는 판별 함수(`is_reader()`)로 열고, 넣기·고치기·지우기에는 제한 정책을 따로 건다.
  - **새 표를 만들 때마다 건다.** `gate.mjs`가 빠진 표를 알려 준다.
- **뷰(view)는 읽기만 준다.** Supabase는 새 뷰에 `anon`·`authenticated` 모두 ALL 권한을 준다. 그대로 두면 로그인 전 방문자가 명단 뷰를 읽고, 로그인한 사용자는 단순 뷰를 통해 원래 표를 RLS 없이 고치거나 지울 수 있다 → `revoke all on <뷰> from public, anon, authenticated` 뒤 `grant select on <뷰> to authenticated`. 뷰를 지우고 다시 만들면 권한이 처음으로 돌아가므로 이 두 줄도 다시 쓴다.
- 소유자 권한 뷰는 RLS가 걸리지 않으므로 **뷰 안에** `where public.is_member()`를 둔다.
- `is_admin()`·`is_member()` 같은 헬퍼 함수는 `security definer` + `set search_path = public`. 정책 안에서 다른 표를 읽어도 무한 재귀에 빠지지 않는다.
- **함수 실행 권한은 `public`에서만 거두면 모자란다.** Supabase는 새 함수에 `anon`·`authenticated` 실행 권한을 따로 준다.
  - 정책에서 쓰는 판별 함수: `revoke execute on function … from public, anon` 뒤 `grant execute … to authenticated`.
  - 서버만 부르는 쓰기 함수(RPC): `revoke execute … from public, anon, authenticated` 뒤 `grant execute … to service_role`. `security definer`인데 함수 안에 권한 검사가 없으면, 실행 권한이 남은 사람 누구나 그 일을 할 수 있다.
  - 확인: `select has_function_privilege('authenticated', 'public.함수이름(인자형)', 'execute');` 대시보드 Security Advisor도 같은 것을 경고한다.

### 서버가 막는 규칙은 DB도 막는다

교사는 자기 토큰(공개 키 + 로그인)으로 데이터 API(PostgREST)를 직접 부를 수 있다. 화면이나 서버 액션에서만 검사한 규칙은 그 길로 우회된다.

- 교사에게 쓰기 정책을 준 표는, 서버 액션이 검사하는 것을 DB에도 건다: 고를 수 있는 종류, 글자 수, 링크 금지, 날짜 범위, 남의 파일 경로, 표시 이름. `with check`, `check` 제약, 제한 정책 중 맞는 것으로.
- 서버만 넣는 값(자동 알림의 보낸 이 이름표, 처리 상태, 확정 표시)은 교사 토큰으로 넣지 못하게 한다. 초안 카드처럼 「교사는 `draft`로만 넣는다」가 같은 모양이다.
- 한 번에 쓰는 값이 남의 자료를 가리킬 수 있으면(사진 경로 등) 「이미 다른 글이 쓰는가」를 `security definer` 함수로 보고 막는다. 지울 때도 다른 글이 아직 쓰면 파일을 남긴다.
- 테스트: 교사 토큰으로 서버를 거치지 않고 직접 넣어 보고 거부되는지 본다.

### 자주 쓰는 정책 모양

| 모양 | 예 | 핵심 |
|---|---|---|
| 본인만 | AI 대화, 내 서명, 푸시 구독, 사용량 | `owner_id = auth.uid()`. **관리자에게도 열지 않는다** |
| 관리자만 + 한 칸 예외 | 설정 표 | 교시 시간 키만 교사에게 읽기 허용 |
| 담당자만 | 결석계 | 관리자 또는 그 반 담임. **읽기와 수정을 같은 기준으로** (보이기만 하고 처리를 못 하는 버그가 있었다) |
| 보낸 사람·받는 사람만 | 넵, 넵 속 일정 | 보낸 사람과 **배달된** 받는 사람만. 예약 중인 것은 받는 사람에게 아직 안 보인다 |
| 시간이 지나면 숨김 | 공지 | `pinned or created_at > now() - interval '24 hours' or is_admin()`. 같은 숫자가 코드에도 있으면 세 곳을 함께 바꾼다 |
| 작성자 + 열 제한 | 자료실 글 | 넣을 때 `created_by = auth.uid()`이고, 파일 경로가 **자기 글의 폴더**를 가리킬 때만(D절 경로 검사) |
| 초안만 넣기 | AI 확인 카드 | 교사는 `status='draft'`로만 넣을 수 있고, 확정은 서버가 |
| 쓰기 정책 없음 | 조직표, 색인, 봇 대화 상태, 로그인 실패 기록 | 시크릿 키(서버)만 쓴다 |
| 비밀 열을 뺀 뷰 | 교실 칠판 | 칠판 토큰 열을 뺀 뷰만 교사에게. 뷰는 읽기만, 안에 `is_member()` |

### 정책으로 어려운 것은 트리거로

「교사는 고정·공개 범위를 못 바꾼다」 같은 **열 단위 규칙**은 정책(`with check`)보다 `before update` 트리거가 맞다. `with check`는 새 행 전체를 보기 때문에, 관리자가 고정한 글은 교사가 제목만 고쳐도 막혔다. 트리거 조건은 `auth.uid() is not null and not is_admin()` — 시크릿 키(서버 작업)는 `auth.uid()`가 비어 있어 통과한다.

### RLS 테스트

- 표나 정책을 바꿀 때마다 **허용과 거부를 둘 다** 테스트한다: 교사 계정으로 「볼 수 있다」, 다른 교사 것은 「0행」, 로그인 안 하면 「권한 오류」.
- **「교직원만」 테스트 파일 하나**가 모든 표를 훑는다: `profiles` 행이 없는(가입만 한) 계정으로 모든 표 「0행」, 휴직·비활성 계정도 같게, 뷰는 고치기·지우기가 거부된다. 새 표를 만들면 그 목록에 더한다.
- 서버만 막던 규칙은 교사 토큰으로 직접 넣어 거부되는지.
- 테스트가 만든 자료는 끝나고 정리한다. 로그인을 많이 하므로 파일을 하나씩 돌린다(함정 30).

## C. 서버 코드·보안 헤더

### 서버 코드

- [ ] 모든 서버 액션·API의 첫 줄은 세션 확인 함수(F절, `04-뼈대설계.md` 3절).
- [ ] 시크릿 키 클라이언트 파일에 `import "server-only"`.
- [ ] 비밀 값 앞에 `NEXT_PUBLIC_`을 붙이지 않는다.
- [ ] 오류 메시지를 사용자에게 그대로 보이지 않는다(데이터베이스 오류에 표 구조가 드러난다). 관리자 화면도 같다. 외부 회사 오류 본문도 그대로 넘기지 않는다.
- [ ] **비밀 값은 비교 함수 하나로 비교한다**(`secretEquals`). 크론 비밀, 외부 봇 키, 공개 화면 열쇠가 모두 이것을 지난다. `===`는 쓰지 않는다 — 앞에서부터 글자를 견주다 멈추므로 걸린 시간으로 한 글자씩 맞혀 볼 수 있다.

  ```ts
  import "server-only";
  import { createHash, timingSafeEqual } from "node:crypto";
  /** 하나라도 비면 false. 양쪽을 같은 길이로 줄여 같은 시간에 비교한다. */
  export function secretEquals(given?: string | null, expected?: string | null): boolean {
    if (!given || !expected) return false;
    const a = createHash("sha256").update(given).digest();
    const b = createHash("sha256").update(expected).digest();
    return timingSafeEqual(a, b);
  }
  ```

  비밀이 설정되지 않았으면 비교 전에 거부한다. 「`Bearer ${비밀}`」은 비밀이 비어도 「Bearer undefined」라는 글이 되어 통과한다(함정 28).
- [ ] **바깥 자료를 앱 안에서 띄우는 화면**(`/open` 같은 감싸 보기)은 링크에 바깥 주소·제목을 싣지 않는다. 「어느 글의 몇 번째 링크」(자료 id와 순번)만 싣고, 서버가 **보는 사람의 권한으로** 그 글을 읽어 주소를 꺼낸다. 주소를 그대로 받으면 누군가 만든 링크 하나로 우리 사이트 머리줄 아래 가짜 로그인 화면을 띄울 수 있다.

### 보안 헤더·CSP

- [ ] 모든 응답: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
- [ ] 다른 사이트가 우리 화면을 감싸지 못하게 `X-Frame-Options: SAMEORIGIN`. 교실 칠판처럼 기기·런처가 감싸야 하는 로그인 없는 경로만 뺀다.
- [ ] `Permissions-Policy`로 **쓰지 않는 기능만** 막는다(예: `camera=(), microphone=(), geolocation=(), payment=(), usb=()`). 녹음처럼 한 화면만 쓰는 기능은 그 경로에서만 연다(`microphone=(self)`). 전체화면·PIP·클립보드처럼 쓰는 것은 막지 않는다.
- [ ] **스크립트 출처를 묶는 CSP**를 건다. 요청마다 새 nonce를 proxy가 만들어 붙인다(`04-뼈대설계.md` proxy 절).

  ```
  default-src 'self';
  script-src 'self' 'nonce-<요청마다 새 값>' 'strict-dynamic';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob: <Supabase 주소>;
  connect-src 'self' <Supabase 주소> <Supabase 실시간 wss 주소>;
  frame-src 'self' https:;          ← 바깥 자료를 iframe으로 띄울 때만
  object-src 'none'; base-uri 'self'; frame-ancestors 'self'; form-action 'self';
  report-uri /api/csp-report
  ```

  - **Report-Only로 시작한다.** `Content-Security-Policy-Report-Only` 헤더로 며칠 지켜보고, 위반 보고가 없으면 막는 헤더(`Content-Security-Policy`)로 바꾼다. 바꾸는 날을 `progress.md`에 적는다.
  - 보고 받는 주소(`/api/csp-report`)는 로그인 없이 열되, **경로·지시어·막힌 출처만** 로그에 남긴다. 보고에는 화면 주소의 `?` 뒤(검색어)와 서명 주소의 토큰이 섞여 온다.
  - 우리가 직접 내보내는 HTML(정적 매뉴얼 등)의 `<script>`에도 그 요청의 nonce를 붙인다.
  - **헤더 덮어쓰기 함정**: CSP는 proxy 한 곳에서만 붙인다. Next는 proxy가 넘긴 **요청 헤더** `content-security-policy`에서 nonce를 읽는다(Report-Only일 때도 같은 정책을 그 이름으로 요청 헤더에 싣는다). `next.config`나 `vercel.json`에서 같은 이름의 CSP를 응답에 따로 붙이면, Vercel에서는 그 값이 요청 헤더를 덮어써 Next가 nonce를 못 찾는다. 막는 쪽이면 화면 스크립트가 모두 멈춘다. 그래서 감싸기 막기는 X-Frame-Options가 맡고, CSP를 막는 쪽으로 바꾸면 정책 안의 `frame-ancestors`가 함께 막는다.
- [ ] 헤더는 경로별 단위 테스트와, 배포 뒤 로그인 없이 도는 E2E(다른 사이트에서 감싸기 차단·칠판은 허용)로 지킨다.

## D. 파일

- [ ] 버킷은 모두 비공개. 받기는 권한 확인 → 짧은(60초) 서명 주소. 화면에 오래 띄우는 사진처럼 길게 둘 것만 용도에 맞게 늘린다.
- [ ] 올리는 경로는 서버가 정하고, 저장 전에 실제 크기를 다시 확인한다. 형식은 확장자가 아니라 파일 앞머리로 확인한다.
- [ ] 시크릿 키로 서명·내려받기·옮기기·지우기 전에 **경로 검사 함수 하나**를 지난다: 정해진 접두사로 시작하는지에 더해 `..`·빈 마디·`%`·`\`·`?`·`#`·제어 문자를 모두 거부한다. `startsWith`만 보면 `../`나 `%2e%2e`로 다른 버킷 파일에 서명된다. 같은 모양 검사를 DB `check` 제약으로도 건다.
- [ ] 크기 한도는 버킷 설정에도.
- [ ] 휴대폰 사진은 서버나 브라우저에서 **다시 그려** 저장한다(긴 변을 줄이고, 사진 속 위치 정보를 뺀다).
- [ ] 비밀번호·학생 명렬표 같은 민감 자료는 「관리자만 보기」로 올리고, AI 검색에서 처음부터 뺀다.

## E. 공개 화면·바깥 통신·로그

### 로그인 없이 열리는 화면

교실 칠판, 학생용 보기처럼 계정 없이 여는 화면은 **긴 무작위 토큰(32자 이상)이 곧 열쇠**다.

- [ ] 토큰을 교사 화면·API 응답·알림 내용·로그에 싣지 않는다.
- [ ] 토큰은 관리자 화면에서만 보이고, 다시 발급할 수 있다. 다시 발급하면 옛 주소·QR은 막힌다.
- [ ] 열쇠 비교는 `secretEquals`(C절).
- [ ] 로그인 없이 여는 경로는 proxy의 **공개 경로 목록 한 곳**에만 적는다. 그 경로는 열쇠를 직접 검사하고, 나머지는 모두 로그인 필요(함정 43). 공개 경로에도 보안 헤더는 그대로 붙는다.
- [ ] **학생·외부인에게 보여 주는 화면**(분실물 함 학생용 보기 등)은 서버가 **허용한 열만** 골라 주는 함수 하나로 그린다. `select *`를 쓰지 않는다. 주인 확인용 특징, 넣은·처리한 교사 이름처럼 교직원끼리만 볼 칸은 싣지 않는다. 검색에 걸리지 않게 `noindex`.
- [ ] 실시간 채널(Supabase Realtime 방송)로 칠판을 깨울 때 **채널 이름에도 토큰을 싣지 않는다.** 공개 채널은 이름을 알면 누구나 듣고 보낼 수 있다. 토큰에서 한 방향(해시)으로 뽑은 이름을 쓰고, 내용 없이 「새 소식 있음」 신호만 보낸다. 신호를 받아도 서버에 묻는 간격에 상한을 둔다(I절).
- [ ] 외부 서비스(카카오 봇 등)가 부르는 주소의 비밀 키는 헤더로 받는다. 주소(쿼리)에 넣으면 접속 기록에 남는다.

### 서버가 바깥 주소를 읽을 때 (AI 주소 읽기 등)

학생 정보를 읽는 도구와 바깥 통신이 한 AI에 함께 있으면, 자료 속 숨은 지시가 정보를 바깥으로 실어 보낼 수 있다. 셋을 모두 지킨다(`07-AI도우미.md` 9절).

- [ ] **AI에게 주소를 여는 도구를 주지 않는다.** 선생님이 글에 붙여 넣은 주소만, AI를 부르기 전에 서버가 읽어 자료로 넣는다.
- [ ] **학교 안·서버 안 주소를 막는다**(SSRF 막기): 사설망, 루프백, 링크 로컬(클라우드 메타데이터 주소 포함), 80·443 밖 포트. 이름을 IP로 바꾸는 **그 순간**에 검사한다(검사 뒤 DNS를 바꿔치기해도 못 들어가게). 넘겨주기(3xx)는 직접 따라가며 매번 다시 검사하고, 횟수·시간·크기에 한도를 둔다.
- [ ] **답 화면에 바깥 링크·그림을 그리지 않는다.** 사이트 안 주소만 링크로 만든다. 마크다운 그림 주소의 `?` 뒤에 학생 정보를 실어 내보내는 길을 막는다.
- [ ] 붙인 자료·드라이브 글은 읽을거리일 뿐 지시가 아니라고 지시문에 적는다.

### 공유 드라이브를 AI가 읽을 때

만드는 법은 `07-AI도우미.md` 10절. 여기서는 지킬 것만.

- [ ] 학교 계정 하나를 전용으로 만들어 그 공유 드라이브에 **뷰어**로만 넣는다. 권한은 읽기 전용(`drive.readonly`), 질의는 공유 드라이브별로만(그 계정에 따로 공유된 파일은 읽지 않는다). 조직 밖 공유를 켜지 않는다.
- [ ] 이 도구만은 교사 세션(RLS)이 아니라 이 계정 권한으로 읽는다. **그 드라이브에 들어간 것은 곧 모든 교사가 AI로 읽는다.** 다른 드라이브·폴더에 이 계정을 넣기 전에 운영자와 정하고 `progress.md`에 적는다.
- [ ] 사진·영상·소리는 목록에도 싣지 않고 읽지 않는다(학생 사진).
- [ ] 열쇠 JSON은 저장소 밖에 두고 환경변수로만 넣는다. 열쇠가 없으면 도구를 내놓지 않는다.

### 로그

- [ ] 로그에 주소의 `?` 뒤(열쇠·서명 토큰·검색어), API 키, 토큰, 학생 이름을 남기지 않는다. 사이트 이름과 사유 코드만.
- [ ] 외부 회사 오류 본문은 읽지 않는다. 요청에 실은 키가 되돌아올 수 있다.

### 바깥 코드(의존성)

- [ ] 저장소 보안 알림을 켜 두고, 프레임워크(Next.js 등) 보안 공지가 나오면 그 주 안에 올린다. 올린 뒤 빌드·단위 테스트·로그인 없는 E2E를 돌린다.
- [ ] 패키지는 이름을 확인하고 넣는다. 꼭 필요한 것만.

## F. 로그인·계정 상태

### 로그인

- [ ] 초기 비밀번호는 사람마다 다른 무작위 값, 첫 로그인 때 변경 강제. 「모두 같은 짧은 숫자」로 통일하지 않는다.
- [ ] 초기 비밀번호 CSV는 배부 뒤 지운다.
- [ ] **틀린 횟수를 제한한다.** 제한이 없으면 흔한 비밀번호 하나를 전 교직원에게 돌려 볼 수 있다.
  - (사람 + 접속 주소)마다 15분에 10번, 접속 주소마다 15분에 100번. 학교는 여러 교사가 인터넷 주소 하나를 같이 쓰므로 주소 한도는 넉넉히 둔다. 사람만으로 묶으면 남이 일부러 틀려 그 교사를 못 들어가게 할 수 있다.
  - 기록 표는 서버(시크릿 키)만 쓴다. 세기·더하기·지우기 함수는 `service_role`에게만 실행 권한(B절).
  - 맞게 들어오면 그 (사람 + 주소) 칸만 비운다.
- [ ] 로그인 화면에 내부 id를 내려보내지 않는다. 교직원 이름 목록을 보일지는 학교와 정하고(`04-뼈대설계.md` 2절), 보인다면 이름·부서만(함정 77).

### 계정 상태

계정은 「활동 중 / 휴직(선택) / 비활성」 중 하나다. 앱과 DB가 같은 기준으로 막는다 — 앱만 막으면 그 사람이 자기 토큰으로 데이터 API를 직접 부를 수 있다.

- [ ] **비활성화**(퇴직·전출): 지우지 않고 `profiles.active = false` → Auth 사용자 차단(`ban_duration`) → 그 사람의 푸시 구독 삭제.
  - 차단을 함께 거는 까닭: 이미 받은 로그인 토큰은 끝날 때까지(기본 1시간) 살아 있다. 차단하면 새 토큰을 받지 못한다.
  - `profiles`를 먼저 바꾼다. 두 번째 호출이 실패해도 더 안전한 쪽이 남는다.
  - 자기 자신은 비활성화하거나 관리자에서 뺄 수 없게 한다.
- [ ] **휴직**(두면): 로그인해서 정해 둔 곳(예: 자료실 읽기·내려받기·비밀번호 바꾸기)만 쓰고, 알림도 받지 않는다.
  - DB: `is_member()`는 「활동 중이고 휴직 아님」, `is_admin()`도 휴직이면 거짓(복직은 다른 관리자가). 휴직에게 열 읽기만 `is_reader()`(활동 중이면 참).
  - 개인 알림과 받는 사람 고르기에서 뺀다.
- [ ] **세션 함수는 비활성·휴직이면 null을 돌려준다**(로그인 안 한 것처럼). 그러면 새 서버 동작·API가 따로 막지 않아도 저절로 닫힌다. 휴직에게 열 곳만 휴직도 돌려주는 함수(`getSessionProfileAny()` 또는 `requireProfile({ allowOnLeave: true })`)를 쓴다(`04-뼈대설계.md` 3절).
- [ ] RLS 테스트에 휴직·비활성 계정을 넣는다(B절).

### 사람·운영

- [ ] 퇴직·전출 교사는 다음 날까지 비활성화한다(학기마다 명단 대조).
- [ ] 관리자는 두 명 이상, 관리자 권한은 꼭 필요한 사람만.
- [ ] 운영 데이터베이스에 직접 붙는 작업(대량 수정·삭제, 마이그레이션)은 시험용에서 먼저.

## G. 개인정보·사생활

### 줄이기

- 쓰지 않을 열은 가져오지도 않는다(교직원 명렬표의 연락처·내선 등).
- 데이터마다 수명을 정하고 크론으로 지운다(`01-설계원칙.md` 5항). 결석·체험학습 접수처럼 건강·가정 정보가 든 것은 **학년도가 끝나면** 지운다(원본 학교: 새 학년도 4월에 지난 학년도 접수를 자동 삭제). 목소리 녹음처럼 민감한 것은 더 짧게(하루).
- 학생 실명은 꼭 필요한 화면(담임이 보는 결석계 등)에만.
- 보는 사람 수는 필요한 만큼만: 결석계는 그 반 담임과 관리자만, 진도 지도는 본인만(「이 반 진도」는 그 반을 가르치는 교사끼리만).
- 붙인 파일 원본과 드라이브 글은 DB에 남기지 않는다. 화면이 그 대화 동안만 들고 있다가 질문마다 함께 보낸다. 예외를 두면(요약 한두 문장을 알림함에 30일 등) 무엇을 얼마나 남기는지 `progress.md`에 적는다.

### 여러 사람이 보는 곳

- [ ] 현황판·아침 알림·교실 칠판처럼 여러 사람이 보는 곳에는 **결강·부재·결석 사유를 싣지 않는다.** 사유는 그 사람 본인의 일정·홈에만.
- [ ] **뷰는 화면이 쓰는 열만** 골라 만든다. 선생님 이름이 필요 없으면 빼고, 「내 것인가」는 뷰 안에서 보는 사람과 견줘 참·거짓으로 준다. 뷰 결과는 교사 누구나 브라우저에서 데이터 API로 그대로 볼 수 있다 — 화면에 안 그린 열도 보인다.
- [ ] 교실·학급 칸처럼 학생이 볼 수 있는 화면에는 교사 이름을 싣지 않는다.
- [ ] 넵(교사 사이의 업무 메신저)과 그 안의 마감·일정은 **보낸 사람과 배달된 받는 사람만** 본다. 학사일정·공유 캘린더에 넣지 않는다.
- [ ] 학생 사진·명렬표는 지정한 사람만 본다. 관리자도 명단에 있어야 하고, 열람 기록·내려받기·AI 도구를 두지 않는다.

## H. AI 도우미 (붙일 때)

- [ ] AI 도구는 **질문한 교사의 세션(RLS)으로** 데이터를 읽는다. 시크릿 키로 읽으면 담임이 아닌 반의 결석계까지 AI가 말해 버린다. 다른 권한으로 읽는 도구(공유 드라이브)는 E절.
- [ ] 보내기·만들기 같은 실행은 확인 카드로 사람이 누른다(`07-AI도우미.md`).
- [ ] 1인 하루 질문 수 한도는 **사용자가 지울 수 없는 사용량 표**에서 센다. 서버가 RPC로 **답을 만들기 전에 한 칸 차지**하고, 실패하면 돌려준다. 대화 기록으로 세면 기록을 지우거나 여러 질문을 동시에 보내 한도를 넘는다. 비싼 모델(깊게 생각하기)의 횟수도 같은 방식으로 따로 센다.
- [ ] 대화 기록은 본인만 보고, 본인이 지울 수 있다. 답 평가에는 대화 내용을 담지 않는다(본인이 「보내기」를 고른 때만).
- [ ] 지시문에 「학생 이름은 최소로, 문서 초안에는 빈칸」을 넣고, 점검 세트로 실제로 지켜지는지 잰다.
- [ ] 바깥 주소 읽기·답 화면 링크는 E절 「서버가 바깥 주소를 읽을 때」.
- [ ] 교사 개인 API 키를 받는 기능이 있으면: 브라우저에만 저장, 서버는 그 요청에만 쓰고 저장·기록·응답에 싣지 않는다. **키 모양을 검사한다**(인쇄 가능한 ASCII만). 제어 문자가 섞인 키는 요청 헤더 오류 메시지에 키가 실려 로그로 샌다(함정 59).

## I. 비용도 보안이다

무료 한도를 넘으면 사이트가 멈춘다. 원본 학교는 교실 칠판 10대가 3초마다 서버에 묻는 바람에 Vercel 무료 한도(월 CPU 시간)를 넘겨 **계정이 정지**됐다.

- [ ] 자주 묻는(폴링) 화면은 간격을 시간대별로 늦추고(원본 학교: 화면이 비면 15초, 밤·주말은 60초), 급한 소식은 푸시·실시간 채널로 깨운다. 깨우기 신호를 받아도 묻는 간격에 상한(예: 2초)을 둔다.
- [ ] AI는 하루 한도 + 회사 콘솔 월 한도(또는 선불 충전).
- [ ] Supabase·Vercel 사용량 화면을 한 달에 한 번 본다(`progress.md` 운영 메모에 적어 두기).
